> 每一条都先核对了**当前代码的真实状态**（避免把"其实能做"写成"没做"），

## 1. F1 的入口按钮 + `Esc` 关闭

> ✅ **已完成。** 四条判据全部实现，另加了"正拖着矩形时 `Esc` 不响应"与
> "光标进出画区域模式跟着变"两条。实现与根因见 `docs/m5-editor.md` §5b-1。

**用户问题**：刚进入的人根本不知道怎么打开编辑器。

**当前状态（核实过）**：

- `F1` 能开能关（`EditorPanel._UnhandledKeyInput` 里 `tt_editor` 动作）—— 但**没有任何可见入口**。
- `Esc` **不能**关：面板打开时 `_UnhandledKeyInput` 把其余按键一律吃掉并标记已处理，
  所以 `Esc` 只被"画区域"模式用（退出那个模式），不会关面板。
- 顶栏左侧已有「存档 ▾」按钮（`Hud._saveButton`，`HudRoot` 下代码建的），
  右边还有「网格吸附」「适配桌面」「100%」三个按钮 —— 加一个编辑器按钮的位置现成。

**要改的**：

1. `Hud` 里加一个「编辑器　F1」按钮（挨着「存档 ▾」），`Pressed` → `RequestToggleEditor()`
   （与 M5 已有的 `SaveRequested` 同一个套路：HUD 不依赖编辑器类型）。
2. `EditorPanel` 订阅它；按钮文字要能反映状态（`编辑器　F1` ↔ `关闭编辑器　Esc`）。
3. `EditorPanel._UnhandledKeyInput`：`Esc` **先关"画区域"模式，再关面板**（两级退出），
   且这个判断要排在"吃掉其余按键"之前。
4. 顺带：面板顶栏那个「关闭　F1」按钮的文字改成「关闭　F1 / Esc」，让快捷键自解释。

**判据**：
- 顶栏按钮存在、矩形在视口内、按下后 `editor.IsOpen == true`
- 再按一下（或按 `Esc`）→ `IsOpen == false`
- 画区域模式打开时按 `Esc`：先退出模式、面板**仍开着**；再按一次才关面板
- 按钮文字随状态变化（否则用户看不出它现在是"开"还是"关"）

## 2. 新建 / 删除卡牌

> ✅ **已完成。** 五个改动点全部实现（「复制这张」走到了 `CardDefinitionService.DuplicateCard`，
> 与本条设想的 `Clone()` + 新 id 一致）。注意**指示物页原先已有新建/删除**，
> 本轮给它补了「复制这个」，两页现在是同一套动作。见 `docs/m5-editor.md` §5b-2。

**用户问题**："当前根本没有新建、删除卡牌的功能。"

**当前状态（核实过）**：**服务层早就有了，界面没接。**

- `CardDefinitionService.CreateCard(objects, name)` / `DeleteCard(objects, id)` 都在，
  卡组页的「新建卡组」用的是同一套写法。
- 自检里已经在用它们（`create_card_appears_in_list` / `delete_unused_card_succeeds` /
  `delete_in_use_card_refused` 三条断言都在跑）。
- **卡牌页的左边只有一列卡，没有任何"新建 / 复制 / 删除"按钮** —— 用户的感受完全正确。

**要改的**：
1. 卡池列表上方加一排按钮：`新建卡牌` / `复制这张` / `删除这张`。
2. 删除走 `DeleteCard`（已有闸门：桌上还有实例就拒绝，并报出张数）→ 失败时 `Hud.Toast`。
3. 删除成功后要**显式 `RefreshList()`**（M5 那轮定的规矩：结构变化谁改谁刷 ——
   `NotifyChanged` 只管顶栏脏标记）。
4. 「复制这张」= `Clone()` 一个定义 + 新 id（`CreateCard` 里那把 `UniqueId` 要复用，
   不能另写一套判重）。
5. 指示物页同样加（它的 `CreateToken` / `DeleteToken` 也早就在了）。

**判据**：
- 点「新建卡牌」→ 卡池多一张、列表多一行、新卡自动被选中
- 点「删除这张」（桌上没有它的实例）→ 卡池少一张、列表少一行
- 点「删除这张」（桌上有实例）→ **不删**，且吐司里出现具体张数
- 复制：新 id ≠ 原 id，且字段是深拷贝（改副本不污染原卡）

## 3. 指示物预览里 4 个形状的位置是歪的

> ✅ **已完成。** 本文对根因的判断（"多算了一次平移"）**实测就是对的**。
> 判据那一版没有照本文的写法走 —— 本文建议的"格子中心取样应等于 `Fill`"
> 第一版就把四个形状全判红了，**而产品是对的**（中心恰好是文字 `"1"`）。
> 最终改成"本格填充像素数 ≥ 理论面积的 40%"+"邻格中心不许有本格填充"。
> 详细过程见 `docs/m5-editor.md` §5b-3。

**用户问题**：4 个形状的图标不在矩形框里。

**当前状态（核实过）**：`TokenPreview._Draw` 里那块代码**确实可疑**，有两个问题：

```csharp
var local   = new Rect2(cell.Position + (cell.Size * 0.5f), cell.Size);   // 用到了，但只是取中心
var centered= new Rect2(-cell.Size * 0.5f, cell.Size);
DrawSetTransform(local.GetCenter(), 0f, Vector2.One);   // ← 平移原点
TokenFaceRenderer.Draw(this, probe, centered, "");      // ← 再按"以中心为原点"画
DrawSetTransform(Vector2.Zero, 0f, Vector2.One);
```

1. **多算了一次平移**：`DrawSetTransform` 已经把原点挪到了格子中心，
   而 `centered` 又是"以原点为中心"的矩形 —— 于是圆心落在 `cell.GetCenter() + cell.Position + cell.Size/2`
   （即**偏了一整个格子的位置**）。正确写法是 `DrawSetTransform(cell.GetCenter(), ...)`
   配 `new Rect2(-cell.Size * 0.5f, cell.Size)`，或者干脆不用变换、
   直接把 `centered` 改成一个**以 `cell.GetCenter()` 为中心**的矩形。
2. **形状框是照着 `cell` 画的、图标却画在别处** —— 所以看起来"框是框、图是图"。

顺带一处：`draw` 里对每个形状都 `new TokenDefinition` 复制一遍字段。
可以接受（预览专用），但如果以后 Token 加字段，这里会**静默漏掉新字段** ——
建议改成 `def.Clone()` 再改 `Shape`，那样加字段时自动跟上。

**判据（像素级，与卡面预览同一套路）**：
- 每个格子的矩形中心取样，颜色应等于该形状的 `Fill`（或与它差 ≤10）
- 格子**四角**取样应**不是** `Fill`（证明图标没有溢出到框外）
- 四种形状各一条 —— 这样"歪了"以后再也不会溜过去

## 4. 画区域这条路的三个问题

### 4a. 画的时候 F1 面板挡着，画完也没关

**用户问题**："在画布上拖矩形点击后没有关闭当前 F1 界面，无法紧跟着划区域。"

**当前状态（核实过）**：
- 画区域时遮罩层铺满的是**面板之外那块**（面板是隐藏面板的子节点时算不出来，
  所以它挂在 `HudRoot` 下、与面板同级、排在后面）。面板本身仍然盖着屏幕
  左侧 1904×996 里的那块 —— 用户能画的只有面板之外的一圈。
- 画完一块区域后 `OnZoneDrawn` 会 `SetDrawMode(false)`，**但面板不关**。
  于是"画一块 → 再画一块"要手动再点一次「在画布上拖矩形」。

**要改的**：
1. 进入画区域模式时**把面板收起**（保留遮罩层与一个小的浮动提示条
   「拖矩形画区域 · Esc 取消」），画完自动把面板放回来。
   这样"整个画布"才真的都是画布。
2. 画完**自动重新进入**画区域模式（连画多块不用反复点按钮）——
   这条要用户拍板：连着画 vs 画一块就退出。

**判据**：
- 进模式后面板不可见、遮罩仍可见、仍能收到鼠标
- 拖完一块：区域数 +1、面板自动回来、选中的是新那块
- 连画两块：中间不需要再点按钮（若决定"连画"）

### 4b. 区域不能拖动 / 改大小

**要改的**：在画布上直接拖区域**边框/角上的把手**来改 `Rect`（这是用户最直观的诉求）。

实现要点（避开已知的坑）：
- **不要用 `_UnhandledInput` 抢事件** —— 项目的第一条设计约定是"输入只有一处入口"
  （`ViewportController`）。所以要给区域系统加一个"被问"的接口
  （像 `IZoneInteraction` 那样），或者让编辑器在"区域编辑模式"下接管。
- 改 `Rect` 必须走 `Zone.ApplyDefinition`（它会重排成员）——
  只改定义不会重排，症状是"框变了、牌还在老地方"。
- 最小尺寸限制（复用 `ZoneEditService.MinDrawSize`）。

**判据**：拖右下角 +100×+50 → `Rect.Size` 精确变化；成员位置跟着重排；
撤销能退回去（如果做成可撤销）。

### 4c. 区域不能删除

**当前状态（核实过）**：**能删**，但入口在「区域」页左下角那个「删除这块区域」按钮，
而且有闸门（区域里还有东西就拒绝，并报出件数）。
用户没找到 → **是入口不可发现的问题，不是功能缺失**。

**要改的（两条一起做才解决"找不到"）**：
1. 区域右键菜单里加「删除此区域」（与「锁定」「摊开」放一起）——
   用户已经在用右键菜单了，那是他最可能去找的地方。
2. 区域被选中时，在画布上显示一个可见的删除把手（或选中框角上的小 ×）。
3. 保留闸门；但被拒时要给出**可操作的下一步**（现在的文案已经说了"先把它们拿出来"）。

## 5. 画布（桌子）的边界

**用户问题**："画布大小不可调整，且画布以外也可以放置东西，那画布没有作用。
应该是拖到画布外的东西就被删除，且划区域也不能超出画布。画布就是桌子。"

**先纠正一处（核实过）**：**画布尺寸其实可以改** ——
「桌面」页有「宽:」「高:」两个输入框和一个「应用尺寸」按钮，改完立刻生效，
自检里 `board_resize_applied` 就是这条。用户没找到 → 与第 1、4c 条同一个问题：
**入口不可发现**。

**真正的缺口（核实过）**：

- `BoardRect` 目前只被三处使用：`Board._Draw`（画底色/网格/边框）、
  相机取景（`FocusOnRect`）、造物落点（`CardDeckService.SpawnOrigin`）。
- **没有任何地方在约束"物件能不能待在桌子外面"**，也没有约束区域不能超出桌子。
  所以用户的感觉是对的：**画布现在只是"一张贴图"，不是一个有边界的东西**。

**要改的（这一条是这一批里最大的一块）**：

1. **定义"桌面外"的语义**：`TabletopObject` 的位置落在 `BoardRect` 之外时算什么？
   要拍板的有三种：
   - **A. 拖出去即删除**（用户提的）——最像真桌子，但误删代价高（不过有 `Ctrl+Z`）
   - **B. 拖出去弹回最近边界**（温和）
   - **C. 拖出去就留在那儿，但在桌面上画一层"桌子外"的暗色区域**（不改变行为，只让边界可见）
   建议：**A + 一个"垃圾桶"组件（第 6 条）同时存在**，而且**拖动时若超界，
   在松手前就显示"将删除"的提示色**（把误删变成可预期的动作）。
2. **区域不能超出桌面**：`ZoneEditService` 在 Create / Mutate 时把 `Rect` 夹到 `BoardRect` 内
   （或者拒绝并说明）。**注意**：这里要选"夹"还是"拒绝"——夹会静默改用户的输入，
   拒绝更诚实。建议拒绝 + 给出可用的最大值。
3. **打印/导出方向的一处连带影响**：`state.json` 里物件的坐标是世界坐标，
   桌面变小之后老存档里的物件可能已经在桌子外 —— 读档时要不要清理？
   建议：**不清理，只警告**（存档不该因为改了桌面尺寸就少东西）。
4. 「桌面」页要**跟着显眼起来**：把「宽/高」挪到页顶并加一句说明
   （"这就是桌子的尺寸；物件拖出桌子会被删除"）。

**判据**：
- 把一张牌拖到 `BoardRect` 外松手 → 物件数 -1（或按拍板的语义）
- 拖到边界内 → 不删
- 画区域时超出桌面 → 被拒/被夹（按拍板），且界面上能看出为什么
- 桌面尺寸改小之后读档：物件数不变，但有警告（如果选了"不清理"）

## 6. 缺的关键组件：垃圾桶、血量显示

**用户问题**："没有一些关键组件，如垃圾桶（删除组件）、血量显示组件
（像显示 60/60 这样的血量而不是指示物血量）等。"

这两条属于**"桌子上的工具件"**这一新类别，与卡牌/指示物/骰子并列。

### 6a. 垃圾桶

- 桌面上的一个固定区域（或用区域系统实现一个"垃圾桶区域"），
  把物件拖进去 = 删除。
- **实现上建议**：不要新造一套，**复用区域系统** ——
  新增一个 `ZoneKind.Trash`（出厂参数：`SortMode.Free`、`Enabled`、
  进入即删而不是留成员）。好处是拖拽路径、命中、右键菜单、存档全都是现成的。
- 如果拖出桌面即删除（第 5 条选 A），垃圾桶就成了"不越界也能删"的那条路 ——
  两者是互补的，不是重复。
- 配套：垃圾桶要有**明显的图标/文字**（现在建在代码里的控件都可以照做），
  以及"拖进去之前"的悬停高亮（可预期）。

### 6b. 血量显示（60/60）

**要拍板的第一件事**：它是**一种新物件**，还是**卡牌字段的一种显示**？

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| **A. 新物件 `StatBoard`** | 桌面上一个可拖的"血量牌"，有 `Current`/`Max`、加减按钮、可自定义标签 | 独立、直观、像实体计数器 | 新 `ObjectKind`、新快照字段、新菜单、新存档兼容 |
| **B. 卡牌字段的可视化** | `CardDefinition` 加一个"把这个字段显示成大号数值"的槽位 | 数据驱动、不改物件种类 | 只能显示卡自己的数值，不能独立于卡存在 |
| **C. 指示物的一种模式** | `TokenDefinition` 加 `ShowAsStat` + `Current/Max` | 复用现有一切 | 指示物本来是"不翻面的小标记"，塞进计数器语义会变味 |

**建议 A**，理由：用户的原话就是"血量显示组件"（组件 = 桌面上的东西），
而且"60/60"这种显示与卡牌的字段（费用/攻击）在语义上是分开的 ——
血量是**对局中会变的状态**，卡牌字段是**卡的定义**。
项目里已经有现成的分类法：`ObjectKind`（Card / Token / Dice）+ `ObjectState` 快照。
加一个新 `ObjectKind.Stat` 是"顺着现有结构长"，不是另起一套。

要一并想清楚的：
- **加减方式**：点击 +1 / 右键菜单 -1 / `Shift`+点击 -1？还是写成两个小按钮？
- **它进不进历史**：改血量必须能被 `Ctrl+Z` 退回去（与骰子点数同一条要求 ——
  骰子点数曾经"不在状态里"，于是撤不掉，那是 M4 抓到的真 bug）。
  这意味着 `ObjectState` 要加字段，`SameAs` 要比它。
- **多段血量**（比如"护甲 3/3"另起一个）→ 其实就是多放几个 Stat 物件，不用特判。
- 是否需要一个**快捷创建**入口（右键物件 → "给它加一个血量"？还是从编辑器放？）。

## 7. 建议的做法顺序

前三条是低风险高收益，建议先做；4、5 需要拍板；6 是新组件，单独一轮。

| 阶段 | 内容 | 理由 | 状态 |
|---|---|---|---|
| **P1** | 第 1 条（入口按钮 + `Esc`）、第 2 条（新建/删除卡牌）、第 3 条（形状位置） | 都是"改完立刻能感觉到"的，且互相独立、不牵动数据结构 | ✅ **已完成**（`docs/m5-editor.md` §5b） |
| **P2** | 第 4 条（画区域的三个子项） | 4a 会碰到"面板可见性 ↔ 遮罩层"那套（M5 已经栽过一次），要小心 | ⏸ 待开工 |

### 本轮（P1）在"做法"上加的三条

P1 实测下来，有三件事比原计划里写的更要紧，后面几阶段直接照用：

1. **断言要量"面积"，不要量"一个点"。** 形状位置那条第一版取"格子中心那一个像素"，
   结果四个形状全红而产品是对的（中心恰好是文字）。
2. **排出去的合成输入必须自己收干净。** 按完键不等帧，残留事件会落到十几步之后的
   另一段探针头上 —— 症状与根因隔得很远。
3. **回退验证之后要 `dotnet build --no-incremental`。** 备份还原保留原 mtime，
   增量构建会继续跑旧 DLL，"修复好像失效了"其实是构建没跟上。
