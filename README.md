# Tabletop Simulator — 2D 桌游玩法原型验证工作台

一个**单人自用**的 2D 桌游玩法原型工具。不是要发布给玩家的产品，目标只有一个：
**快速搭出一个桌游玩法原型，然后反复试玩、改数值、回退，验证它好不好玩。**

因此取舍是刻意为之的：

| 优先 | 不做 |
|---|---|
| 造卡快（文本/数值驱动，不必做美术） | 网络联机 |
| 布桌快、重开快 | 玩家权限 / 隐藏信息校验 |
| 改一个数值 → 立刻试玩 | 物理引擎（骰子纯数字滚动） |
| 操作错了能立刻回退 | 美术打磨、发布打包 |

## 怎么跑

**编辑器里**：用 Godot 4.7.2 **.NET（mono）版**打开本目录，按 F5。

**命令行**：

```powershell
dotnet build TabletopSimulator.csproj
& "<Godot .NET 版的可执行文件>" --path .
```

> 必须用 **.NET（mono）版** Godot，标准版跑不了 C#。
> `tools/dev/shot.ps1` 会自己找它：先查 `PATH`，再查常见安装目录，
> 最后遍历各盘符下的 `SteamLibrary\steamapps\common\Godot Engine`。
> 装在别处就设环境变量 `TT_GODOT_EXE`，或给脚本传 `-GodotExe`。

> **关于 `addons/`**：那里面只有 Godot AI MCP 插件，是**开发工具，不是项目依赖** ——
> 它没有入库（`.gitignore` 挡着），游戏代码只依赖 Godot 本身。
> 但 `project.godot` 里有两条对它的引用（运行时 helper autoload + 编辑器插件）。
> **新克隆下来的人**二选一：装一份同样的插件，或者把那两条删掉：
>
> ```
> [autoload]        → 删掉 _mcp_game_helper 那一行
> [editor_plugins]  → enabled 改成 PackedStringArray()
> ```
>
> 不装也不删的话，编辑器启动时会为找不到的文件报错 —— 不影响游戏本身，只是吵。

### 操作

**视角**

| 操作 | 按键 |
|---|---|
| 缩放（以鼠标位置为锚点） | 滚轮 |
| 平移画布 | 中键拖拽 / 右键拖拽 / `空格`+左键拖拽 |
| 适配整张桌面 | `Home` |
| 复位到 100% | `Ctrl`+`Home` |

**物件**

| 操作 | 按键 |
|---|---|
| 拖拽物件 / 整堆 | 左键拖 |
| 框选 | 左键在**空白**处拖 |
| 从堆中抽单张 | `Shift` + 拖拽 |
| **框选几张已摆好的牌挪位置** | 左键拖 —— **仅移动**，保持原来的排列，绝不会自动合并 |
| **翻面** | `F` —— **指着一摞牌时 = 整个牌堆反过来**（次序反转 + 正反面全翻）。只动一张请 `Shift`+拖抽出来 |
| **洗牌** | `R` —— 指着哪一摞就洗哪一摞（桌面自由堆、牌库、弃牌堆都行） |
| 步进旋转 ±15° | `[` / `]`（`Q` / `E` 同义） |
| 无级旋转 | `Alt` + 滚轮 |
| 复制 | `Ctrl`+`D` |
| 删除 | `Delete` |
| 全选 / 取消选中 | `Ctrl`+`A` / `Esc` |
| 网格吸附开关 | `G` 或顶栏按钮 |
| 掷骰 | **轻点骰子**（或右键 → 掷！） |
| 上下文菜单 | 右键轻点物件 |

**撤销 / 重做 / 日志**

| 操作 | 按键 |
|---|---|
| 撤销 | `Ctrl`+`Z` |
| 重做 | `Ctrl`+`Shift`+`Z`（`Ctrl`+`Y` 同义） |
| 操作日志面板 | `Tab` |
| **回到某一步** | 在日志面板里**点那一行** |
| **打开运行时编辑器** | `F1`，或点顶栏的「编辑器　F1」按钮 |
| **关闭编辑器** | `Esc`（编辑器开着时）。画区域模式开着时**第一下先收模式、第二下才关面板** |

日志面板里每行是「序号 + 中文描述 + 相对时间」，**比当前步新的行变暗标「可重做」**——
点它等于走回去。这就是这个工具最常用的一件事：*刚刚那步改了什么、怎么改回去*。

撤销的粒度有两处刻意设计：**一次拖拽 = 一条历史**（不是每帧一条），
**连击在同一组目标上会合并**（连按两次 `]` 合成"旋转 30°"一次退回）。
骰子**也在历史里** —— `Ctrl+Z` 能把点数一起退回去。

> 拖拽途中按 `Ctrl+Z` 会被拒绝并提示"先松开鼠标"：一次手势的起点快照取自按下那一刻，
> 中途撤销会让那个起点不存在，历史从此与真实状态错位。

**存档**

| 操作 | 按键 |
|---|---|
| 打开存档菜单 | 顶栏「存档 ▾」 |
| 立即保存 | `Ctrl`+`S` |
| 另存为 | `Ctrl`+`Shift`+`S` |
| 新建 / 切换 / 重命名 / 删除 | 存档菜单 |

**启动会自动载入上次的存档**（首次运行才用示例内容）。
一个存档 = 一个自包含目录，可以整个拷走：

```
<存档根>/saves/<存档名>/
  project.json   卡牌定义 / Token 定义 / 区域定义 / 桌面主题
  state.json     当前对局：全部物件 + uid 计数器 + 区域成员次序
  images/        这个存档导入的图片
  thumbs/        存档缩略图
<存档根>/logs/history.jsonl    操作流水（一行一条 JSON，可 diff）
```

> 两个 JSON 都是**给人看的**：缩进、中文不转义、颜色写 `#rrggbbaa`、向量写 `[x, y]`。
> 手改坏了也不会崩 —— 指向不存在的定义会跳过那个物件并打警告。
> 定义那一半与对局那一半拆开，是为了 M5 的运行时编辑器只需要动前者。

**运行时编辑器（`F1`）**

游戏内打开，**五个分页**。改完**立刻生效**，落盘要显式保存（顶栏会显示「未保存改动」）。

| 分页 | 能做什么 |
|---|---|
| **卡牌** | 卡池列表 + 「**新建卡牌 / 复制这张 / 删除这张**」+ **卡面实时预览**（正/背两面）；三段表单：基本（名称 / 底图 / 卡背 / 三种颜色 / 导入图片）、**卡面字段增删改**（键 / 标签 / 值 / 槽位 / 字号 / 颜色 / 带不带标签）、**版式**（三种字号 / 内边距 / 圆角 / 边框宽 / 投影 / 三种文字色） |
| **指示物** | 列表 + 「新建 / **复制这个** / 删除 / 放到桌面」+ **四种形状并排预览**（当前那档加黄框）+ 全属性 |
| **卡组** | 一副牌的配方（哪种卡几张）+ 一键发到某个区域，或散到桌面 |
| **桌面** | 背景图 / 底色 / 尺寸 / 网格 |
| **区域** | **在画布上拖矩形画一块区域**，或改已有区域的全部参数 |

**打开与关闭**：顶栏有一个「编辑器　F1」按钮（文字会随状态变成「关闭编辑器　Esc」），
按 `F1` 也行。关掉可以再按一次，或按 `Esc`。

三件事值得单独说：

- **预览与桌上的卡用的是同一个渲染函数**（`CardFaceRenderer.DrawFace`）。
  预览只是换一个 `CanvasItem` 再画一遍 —— 不可能出现"预览好看、桌上不一样"。
- **改一张卡的定义，桌上所有同名卡立刻跟着变**（实例级覆盖不受影响：
  那是"这一张和别的不同"，不该被模板改动冲掉）。
- **删掉还有人在用的东西会被拦住**：桌上还有 7 张牌在用这张卡定义、
  牌库里还有 15 张牌，都会告诉你具体数字，而不是删完让你自己发现。

> **导入的图片存在存档目录里，不进 Godot 的资源系统** —— 所以改图、换图立刻生效，
> 不用重新导入、不用重启。一个存档的 `images/` 跟着存档走，整个目录可以拷给别人。

> **「画区域」是一个模式**：打开后整个桌面变成一块画布，拖出矩形就建出一块区域，
> 松手自动选中并退出模式。`Esc` 或关掉面板都会收掉它 —— 免得回到桌面
> "突然拖不动牌了"却看不出原因。

**「指着一摞牌 = 指着整摞」**

牌堆是一个整体。鼠标停在一摞牌上按 `F`，得到的是**整个牌堆翻过来**——底牌变顶牌、
正反面全翻（物理上把一摞牌拿起来翻个面就是这个结果），而不是"恰好被指到的那张翻个面"。

> 一条好用的判据：**一张牌背靠背叠在另一张上**（底牌盖放、顶牌朝上，上下看都是牌面）时，
> 整摞翻过来**仍然显示牌面** —— 底牌翻上来时朝向也跟着翻了。
> 如果翻完变成了卡背，说明那次只翻了顶上那一张，整摞并没有真的翻转。

**想只动一摞里的某一张**：`Shift`+拖把它抽出来，或者右键它用物件菜单。

**选中多张时以选中集为准**（框选完再按 `F` 就翻那一组）。
但**只选中一张不算数**——那多半是拖拽留下的残留（拖完一张牌它仍是选中状态），
若把它当成"我要单独操作这张"，整摞翻转就会悄悄退化成逐张翻面：只把顶上那张翻过去，
而牌堆次序根本没动。

**拖拽多张时会不会自动成堆？看「从哪来」**

这是两条实测反馈逼出来的规则 —— 两个动作在手上完全一样，只能靠来源区分：

| 拖的是什么 | 落在空地 | 压在别的牌上 |
|---|---|---|
| **单张** | 脱离原堆，变散件 | 并进那一堆 |
| **整堆**（拖已有的一个堆） | 只换位置，堆不变 | 并堆（把两堆合成一堆） |
| **从区域里抓的一把** | **叠成一摞** | 只移动 |
| **桌面上框选的一把散牌** | **仅移动，保持排列** | **仅移动** |

> 桌面上排好位置的一把牌，框选拖走只是想换个地方摆 —— 自动成摞等于把排列毁掉，
> 而用户从没表达过"要堆起来"。反过来，从手牌 / 牌库里抓一把出来，那就是"一把牌"。

**区域**

| 操作 | 按键 |
|---|---|
| 把牌放进区域 | 拖到区域上方松手 |
| 从区域取出 | 拖出来（落点不在任何区域即脱离） |
| **从区域里拖一把出来** | 落在空地 → **自动叠成一摞**（右上角显示张数）。一次手势拿起 N 张、放下就是 N 张一摞 |
| 从牌库 / 弃牌堆抽最上面一张 | `Shift` + 拖拽（同「从堆中抽单张」） |
| 双击牌库抽牌 | **双击牌库**（或鼠标停在牌库上按 `D`） |
| 洗牌 | 鼠标停在**任意一摞**上按 `R`（牌库 / 弃牌堆 / 桌面散牌堆都行） |
| 区域菜单 | 右键轻点区域空白处；**右键点在牌库里的牌上弹的也是区域菜单** |
| 拆散一摞 | 右键那摞牌 → 拆散这堆 |
| 切换手牌排版 | 区域菜单 → 排版：横排 / 扇形 |
| 查看区域里有什么 | 区域菜单 → 查看区域（摊开） |
| 锁定 / 解锁区域 | 区域菜单 → 锁定此区域 |

> **右上角那个数字什么时候出现**：只在这张牌确实处在**一个 ≥2 的堆里**、且它是堆顶时。
> 落在区域里的牌不算 —— 区域的张数显示在区域自己的标签上（`手牌 5`）。

区域的行为由定义决定，不是写死的：**排版**（自由 / 叠放 / 横排 / 扇形）、
**进区朝向**（强制翻开 / 强制盖放 / 不动）、**是否吸附归位**、
**容量上限**（满了整次拖入被拒，并**退回原处**）、**双击是否抽牌**、**抽到哪个区域**。

> 为什么「右键点牌库里的牌」弹的是区域菜单而不是卡的菜单：一摞牌的正确操作单位是
> **这一摞**（洗牌 / 抽牌 / 全部翻开），而不是"恰好被点到的第 7 张牌"。
> 手牌区、出牌区这些非叠放区域仍然是**每张牌各自可操作**。

**操作的落点规则（「悬停即为选中」）**

键盘与 `Alt`+滚轮操作的作用目标是这样决定的：

1. 鼠标**悬停**在某个物件上 → 就操作它，**不必先点一下**；
2. 悬停的物件**本身已在选中集里** → 操作整个选中集
   （框选完之后鼠标通常还停在其中一个上，此时若只操作那一张，框选就白做了）；
3. 什么都没悬停 → 操作选中集。

描边只表达一件事：**亮黄 = 下一次操作会改到它；暗黄 = 在选中集里，但当前不是目标。**
所以把鼠标移到别的卡上时，原来那张会立刻变暗 —— 一眼就知道 `F` 会翻哪一张。

**区域也遵守同一条规矩**：`S` 洗牌 / `D` 抽牌的落点是**鼠标悬停的那个区域**，不必先点选。

左键动作的优先级则是分开定的，每条都有具体理由：

| 动作 | 优先级 | 为什么 |
|---|---|---|
| 左键点击 / 框选 | **物件优先，区域不吞普通左键** | 区域是「位置」不是「容器」。如果它像面板一样吞掉左键，在出牌区里框选就废了 |
| 右键 | **叠放区域（牌库/弃牌堆）优先于物件**；其它排版物件优先 | 一摞牌的操作单位是"这一摞"，不是"恰好被点到的第 7 张牌" |
| 双击 | **区域优先于物件** | 牌库最上面那 3 张牌正好压在自己的矩形中心，双击"牌库"命中的几乎总是顶牌 —— 按物件优先的话，抽牌这个最常用操作永远触发不了 |

**鼠标离开物件时会取消选中**（单选情况下）。否则会出现「点过一张卡之后鼠标移开，
它仍是选中状态、描边还亮着，按 F 还会翻它」的怪现象。

两种情况下刻意**不**清，因为清了反而难用：

- **正在拖拽** —— 拖拽途中鼠标必然会「离开」被拖的物件（它被排除在拾取之外），
  一移动就清的话拖到一半就丢选中了。
- **多选**（框选 / `Ctrl`+点选建立的多于一个）—— 那是刻意建立的集合，
  不该被一次鼠标移动冲掉，否则框选完立刻失效。多选要取消用 `Esc` 或点空白。

> 网格吸附用独立开关而不是修饰键，因为它是**持续状态**而非一次性动作。
> `Shift` 因此腾出来做「从堆中抽单张」。

## 怎么验证

不靠肉眼看图，靠**可复现的机械断言**：

```powershell
powershell -File tools/dev/shot.ps1 -Name m2_objects -Frames 50
```

它会拉起游戏、等 N 帧、截图、跑自检、退出（**不需要窗口焦点**，可反复执行）。产出三份东西：

- `.dev/shots/<名字>.png` —— 画面
- `...png.meta.json` —— 分辨率 / 采样颜色数 / 平均亮度
- `...png.report.json` —— 自检报告

报告里的证据分十七类（每一类在报告里各有一个 `pass` 字段）：

1. **字体**：用 `Font.HasChar` 逐字检查中文码位是否有字形 → `verdict: CJK_OK`
2. **像素**：分区域统计主色与颜色数 → 桌面主色应精确等于 `BoardTheme.BackgroundColor`
3. **UI**：关键 `Control` 的实际矩形与文本 → 检查有没有跑出屏幕、有没有被压成 0 宽
4. **相机**：缩放锚点不变量 —— 缩放前后该屏幕点下的世界坐标必须不变
5. **物件与输入**：用 `Input.ParseInputEvent` 往真实输入管线塞伪造鼠标/键盘事件，
   验证从「输入路由 → 物件管理器 → 节点状态」整条链路
6. **区域一致性不变量**（八条）：成员关系双向一致、无重复成员、无孤儿声明、
   自由堆与区域互斥、叠放序号连续、可见深度正确、**徽章只在真的叠放时出现**
7. **区域端到端**（`zone_simulation` 节，100+ 条布尔量）：洗牌可复现、双击抽牌抽到的是原顶牌、
   手牌排版不重叠不越界、进区强制朝向、满容量整次拒绝并退回原处、锁定拒绝、拖出后可见性恢复、
   **进出牌库不留残留**、**桌面散牌框选拖拽只移动不成堆**、**从手牌抓一把仍然成摞**
8. **拆桌检查**：清空所有区域之后，桌面上不留孤儿声明与幽灵徽章
9. **JSON 地基**（`json_simulation`）：四种定义各造一份 → 序列化 → 反序列化 → 逐字段比；
   外加"枚举写成名字""颜色写成哈希""中文不转义""字段清单"（加字段时照着核对）
10. **快照写回**（`undo_simulation`）：把游戏折腾一百多次之后写回开局快照 → **逐字段比对**、
	区域成员次序、绘制次序、uid 唯一性与计数器、八条不变量
11. **裁判自己也要被验证**（`invariant_probe`）：注入 5 种**真实 bug 的样子**，
	要求每一条恰好触发对应的那条不变量。没有这一节，"撤销之后一致性全绿"这句话毫无价值
12. **撤销流程**（`undo_flow_simulation`）：用户实测报的那条路径 ——
	**撤销到底必须回到开局的桌面**、每一步撤销都不许写历史、重做必须原样回来
13. **历史本身**（`history_simulation`）：一次拖拽恰好 1 条、**每个入口恰好 1 条**、
	连击合并、手势中拒绝撤销、时间旅行、**每条描述非空且是中文**
14. **日志面板**（`log_panel`）：面板矩形的宽度/高度/位置/是否让开顶栏底栏，
	外加"面板矩形里颜色数 ≥ 20"（纯色板是 1~2 种，实测 257 —— 矩形量对、
	`Visible` 为真，都还可能是"一块和桌面同色的空板"）
15. **存档**（`save_simulation`）：复杂局面 → 保存 → **把桌子打乱** → 读档 → 逐字段比对；
	连续读两次不撞 uid、手改坏了要优雅降级（真的去改磁盘上的文件）、
	列表 / 改名 / 删除 / `last_save` 跟随
16. **徽章像素**（`badge_render`）：成对取样 —— 堆顶应有徽章像素、正面散件应几乎没有
17. **运行时编辑器**（`editor_simulation`，247 条）：面板矩形（**宽高非零**、在视口内、
	不压顶栏）、**五个分页**能切、卡池列表与卡池一致、**预览里能找到与定义相符的填充色**、
	**卡面字段增删改**（加完定义真多一项、改完能从表单读回来、换卡不许把 A 的值写进 B）、
	**版式参数**、图片导入（字节一致 / 同名同内容复用 / 同名不同内容改名）、
	**顶栏入口按钮**（按下开关面板、文字随状态变）、**`Esc` 两级退出**、**卡池的新建/复制/删除**
	（复制必须是深拷贝：改副本原卡一个都不许变）、**指示物预览四个形状的几何**
	（本格填充量 ≥ 理论面积的 40%、邻格中心不许有本格填充）、
	**指示物页**（放到桌面真的多一个 Token 且带着选中的定义）、发牌张数恰好对、
	画区域的整条拖拽链路（**遮罩吃掉了按下**、矩形尺寸对、画完选中并退出模式）、
	**删除闸门带反例**（有实例时拒绝 + 空定义删得掉）、
	以及一条**端到端**：新建存档 → 导图 → 造卡 → 组卡组 → 画区域 → 发牌 → 布桌面 →
	**开玩**（画手牌区、用区域页表单把抽牌目标指过去、双击抽一张、翻面、换排版、撤销）→
	存盘读回 → 收拾干净

> **一条重要约定**：某一节的报告里如果**没有 `pass` 字段**，表示它**没跑**（`skipped`），
> 而不是失败。近景截图（`-Zoom 1.0`）下桌面大半在视口外，探针找不到靶子，这时就是 skipped。
> 「测试说谎比不测更危险」—— 所以"没条件跑"必须和"跑挂了"长得不一样。

### 隔离：自检绝不碰你的真实存档

`shot.ps1` / `godot_run.ps1` 会自动附加两个参数，**别手工去掉**：

## 几个关键设计决定

**1. 数据用 POCO + JSON，不用 Godot `Resource`/.tres**
存档要可读、可手改、可 diff —— 对调试工具这比二进制化重要得多。
`Color` / `Vector2` 走自定义 JsonConverter，JSON 里就是 `"#3b4252"` 这种能直接改的写法。

**2. 卡面用 `_Draw()` 合成，不用 `Control` 节点树**
一张卡 = 1 个 `Node2D`。几百张卡时 Control 的 layout 开销会炸，
而 `Node2D` 天然支持自由旋转缩放，和「像素级自由拖拽」的交互模型完全契合。

**3. 卡牌字段是 `List<CardField>` 而非固定属性，且支持实例级覆盖**
玩法验证时字段集合本身就在变（今天 cost/atk/hp，明天加「关键词」），
所以字段必须是数据。而改某一张卡的数值不该污染定义、更不该影响牌库里另外三张同名卡 ——
这是验平衡性时的核心操作。

**4. 相机目标值与当前值分离**
所有数学（尤其是「鼠标下的世界点保持不动」）作用在目标值上，
每帧用指数平滑逼近当前值。这样既平滑，又不会因为 Godot 相机变换晚一帧生效而算错锚点。

**5. 输入只有一处入口**
`ViewportController` 是唯一的输入路由，物件系统通过 `IWorldPicker` /
`IWheelHandler` 接口被"问"而不是自己去抢 `_UnhandledInput`。
否则谁先拿到事件取决于节点顺序 —— 那种 bug 极难查。

**6. 堆是纯逻辑分组，不新增节点**
成员仍是容器节点的直接子节点，只是位置对齐、绘制次序排成连续。
于是「拆堆」「并入」都是纯数据操作，没有节点增删，也就没有生命周期与释放顺序的坑。

**7. HUD 用 VBox + 弹性 Spacer，不用锚点的 `minsize` 模式贴底**
M1 实测踩过：用 `anchor_preset=bottom_wide` 的 `minsize` 模式时，
容器最小尺寸还没算出来，偏移量按 0 计算，提示条被推到 `y=1080`（屏幕外）、
吐司被压成 1px 宽。声明式布局免疫这类时序问题。

**8. .ps1 脚本一律纯 ASCII**
Windows PowerShell 5.1 对无 BOM 的 UTF-8 文件按 ANSI 解码，
中文会变乱码并撑破字符串引号导致解析失败。C#/GDScript/文档里的中文不受影响。

**9. 区域成员的唯一真相是 `TabletopObject.ZoneId`，不是 `Zone.Members`**
两者是双簿记（一份在物件上、一份在区域上），所以自检里专门有**八条一致性不变量**盯着它们。
一旦不一致，症状是"牌库显示 20 张、实际只能抽出 19 张"这种**看起来只是数字不对**的问题，
靠人眼和普通断言都极难定位 —— 所以把它变成一条红/绿。

**10. `PileId` 与 `ZoneId` 互斥：区域叠放**不复用** `Pile` 对象**
直觉上"牌库就该是一个堆"，但把两者的生命周期接起来会有四处打架：
`Pile` 在成员剩 1 个时会自行解散、它的 `MergeInto` 会把区域成员并进桌面上的自由堆、
`ResetPileFields` 会把"只画最上面 3 张"改回全可见。
所以区域自己排版（约 15 行），只复用它的阶梯公式与徽章字段。

**11. 区域成员在拖拽「起点」就脱离区域，落点被拒时送回原处**
若在落点才脱离，拖到桌面会留下「还在牌库里、位置却在桌面」的半截状态
（张数算错、下次重排还会把它吸回去）。而落点被拒（满了/锁了）时不送回原处的话，
用户看到的是"我手滑了一下，牌没了归属"。

**12. 双击判定是自己算的，不用 `InputEventMouseButton.DoubleClick`**
那个标志由 DisplayServer 层填写，而自检是把合成事件直接塞进 `Input.ParseInputEvent` 的，
走不到那一层。用它的话，"双击抽牌"在真机上能用、在自检里永远触发不了 ——
**这条最核心的新交互就成了自检覆盖不到的盲区**。自己判定只多十余行代码，
换来的是合成事件与真实鼠标走完全相同的路径。

**13. 会「长满」的区域，尺寸按上限反推**
手牌区一开始按"5 张差不多"估了 1500 宽，第 5 张卡就换行掉到区域外。
改成按 10 张反推 3168 宽。凡是容量可增长的区域，尺寸必须按上限算。

**14. 撤销不是「反向操作」，是「把快照写回去」**
每条命令写自己的 `Undo()` 都要正确可逆：并堆的逆是拆堆 + 恢复次序 + 恢复锚点；
抽牌的逆是放回牌库**顶**并恢复盖放；区域移出的逆要同时恢复三个字段。
**漏一个字段就是"数据全对、只是画错"那类 bug** —— M3 的张数徽章已经栽过一次。
快照写回只有一条恢复路径，正确性只取决于"快照是否完整"，而完整性是**可断言**的。
代价是每次操作存两份全表快照（300 步上限），对这个规模的桌面完全不是问题。

**15. 读档复用撤销的写回路径，不另写一遍**
`SaveSystem.Load` 把 `state.json` 装进一份 `SceneSnapshot` 再 `Restore`。
写回顺序（区域对齐 → 丢弃陈旧堆 → 物件状态 → 重建堆 → 区域成员 → 绘制次序 →
归一化派生残留 → uid 复位）是撤销的自检反复折腾过的，
"解散旧堆排在半途会清掉刚写好的 `PileIndex`"就是在那里查出来的。
读档自己再写一遍，等于把那个坑重新挖开，而且两份实现迟早分叉。

**16. 诊断信息要留在报告里，别只留在脑子里**
`UndoSystem` 有一组只读计数器（记了几次、被什么挡掉、截断了几条）、
`SaveSystem` 有 `LastError` 与区域账本、`LogPanel` 有落盘 trace。
加它们不是为了好看：这一轮所有"静默失败"型 bug 都是靠这些数字定位的 ——
**遇到自相矛盾的读数时，加一个只读计数器比继续推演快得多。**

## 自检的硬规矩

写自动化断言时踩过的坑，记在这里免得重犯：

1. **不要写死帧数。** 帧率随环境变化（本机实测跑在 ~165 FPS，不是 60）。
   骰子动画最初写死等 110 帧，结果动画根本没跑完就判定失败。
   现在一律**轮询直到条件成立**。
2. **不要写死屏幕坐标。** 桌面内容一变，写死的点就可能正好压在物件上，
   于是「点空白」根本没发生、断言假失败。现在一律**运行时探测**
   （空位、屏幕内目标）。

还有一条更隐蔽的：**聚合判定里的键名必须和子项写入的键名一致**。
曾经写成 `duplicate_ok` 而实际是 `dup_ok`，导致五项子断言全绿却报失败，
差点去改本来正确的产品代码。测试说谎比不测更危险。

M3 又补了三条：

3. **「没条件跑」必须和「跑挂了」长得不一样。** 近景视角下桌面大半在视口外，
   探针找不到靶子，断言会红 —— 但那不是产品有 bug。约定：该节的报告里
   **没有 `pass` 字段** = 没跑。否则一条红会把人引向完全错误的方向。
4. **探针找「空白点」不能是「取第一个通过的，扫不到就猜一个」。**
   猜出来的点可能正好压在物件上、还落在区域里 —— M3 就因此让三处**互不相关**的
   断言同时变红，查了很久才发现是同一个坐标在作祟。
   现在改成全局找最空的点，并把「空旷度」写进报告，让断言自己交代可信度。
5. **旧断言会因新功能而失效，这时要改断言、不要改产品。**
   牌库让 17 张牌不可见，于是 `dup_ok` 的 `selected == before`（隐含"所有物件都可见"）
   必然为假。同理，`FindLooseCard` 这类辅助函数要跟着新概念升级 ——
   牌库顶牌原来也满足「不属于堆且可见」，于是 M2 的堆叠/右键断言开始去测牌库里的牌。

6. **离开一个"语境"时必须把该语境留下的字段清干净，而且要收成一个方法。**
   用户实测抓到一个 bug：把牌放进牌库再拖出来，右上角仍挂着牌库的张数（「30」）。
   根因是移出区域时只清了 `ZoneId`、没清 `PileIndex`/`PileCount`，
   而徽章条件恰好是「`PileCount >= 2` 且 `PileIndex` 是最后一个」——
   当上"最上面一张"的牌正好满足，于是徽章跟着它走了。
   **数据全对、只是画错**，最难查的一类。现在统一走 `ClearStackVisual()`。

7. **"开局快照"式的不变量抓不到运行期的 bug。**
   上面那个徽章 bug，启动快照那份不变量**照样全绿** —— 因为它跑在所有操作之前。
   真正报红的是跑完一整套操作之后复查的那一份。
   两处都要有，并且要在报告里写清楚各自的时间点，否则会给人"一直在被保护"的错觉。

8. **新写的断言要证明自己抓得住 bug。** 修完之后我把它回退了一次，
   确认确实变红（并留下了精确诊断：`card-0002 … count=16`），再恢复。
   否则很容易写出"永远绿"的假断言 —— 尤其是那种"先确认前置成立、再断言结果"的两段式，
   前置不成立时如果一路 `return`，它就永远不会失败。

9. **"逐个移除 + 逐个重排"会级联，批量操作必须最后只重排一次。**
   从横排的手牌里一次拖走 10 张，被打包拖走的每一张都先被重排到了**槽位 0**
   （因为每次摘掉一张，剩下的就从槽位 0 重新铺，下一个被摘的于是也在槽位 0），
   结果 10 张塌成一点、还跟不上光标。用户描述的"它确实是一堆卡片"就是这个假象。
   修法：先把成员全部摘掉，**最后对受影响的区域排版一次**（`ZoneManager.LeaveZones`）。

10. **像素级断言不能只比对"主色"。** 徽章画不画，对卡面主色毫无影响 ——
   所以"成了一堆却没有数字"能一路穿过所有既有探针。要单独验的东西就得单独验，
   而且必须配一个**对照组**（堆顶应当有徽章、正面散件应当没有）。
