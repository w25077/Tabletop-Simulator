# Tabletop Simulator — 2D 桌游玩法原型验证工作台

一个**单人自用**的 2D 桌游玩法原型工具。不是要发布给玩家的产品，目标只有一个：
**快速搭出一个桌游玩法原型，然后反复试玩、改数值、回退，验证它好不好玩。**

因此取舍是刻意为之的：

| 优先 | 不做 |
|---|---|
| 造卡快（文本/数值驱动，不必做美术） | 网络联机 |
| 布桌快、重开快 | 玩家权限 / 隐藏信息校验 |
| 改一个数值 → 立刻试玩 | 物理引擎（骰子纯数字滚动） |
| 操作错了能立刻回退 | 美术打磨、发布打包 |

## 怎么跑

**编辑器里**：用 Godot 4.7.2 **.NET（mono）版**打开本目录，按 F5。

**命令行**：

```powershell
dotnet build TabletopSimulator.csproj
& "D:\SteamLibrary\steamapps\common\Godot Engine\Godot_v4.7.2-stable_mono_win64_console.exe" --path .
```

> 必须用 **.NET 版** Godot。标准版跑不了 C#。

### 操作

**视角**

| 操作 | 按键 |
|---|---|
| 缩放（以鼠标位置为锚点） | 滚轮 |
| 平移画布 | 中键拖拽 / 右键拖拽 / `空格`+左键拖拽 |
| 适配整张桌面 | `Home` |
| 复位到 100% | `Ctrl`+`Home` |

**物件**

| 操作 | 按键 |
|---|---|
| 拖拽物件 / 整堆 | 左键拖 |
| 框选 | 左键在**空白**处拖 |
| 从堆中抽单张 | `Shift` + 拖拽 |
| 翻面 | `F` |
| 步进旋转 ±15° | `[` / `]`（`Q` / `E` 同义） |
| 无级旋转 | `Alt` + 滚轮 |
| 复制 | `Ctrl`+`D` |
| 删除 | `Delete` |
| 全选 / 取消选中 | `Ctrl`+`A` / `Esc` |
| 网格吸附开关 | `G` 或顶栏按钮 |
| 掷骰 | **轻点骰子** |
| 上下文菜单 | 右键轻点物件 |

**操作的落点规则（「悬停即为选中」）**

键盘与 `Alt`+滚轮操作的作用目标是这样决定的：

1. 鼠标**悬停**在某个物件上 → 就操作它，**不必先点一下**；
2. 悬停的物件**本身已在选中集里** → 操作整个选中集
   （框选完之后鼠标通常还停在其中一个上，此时若只操作那一张，框选就白做了）；
3. 什么都没悬停 → 操作选中集。

描边只表达一件事：**亮黄 = 下一次操作会改到它；暗黄 = 在选中集里，但当前不是目标。**
所以把鼠标移到别的卡上时，原来那张会立刻变暗 —— 一眼就知道 `F` 会翻哪一张。

**鼠标离开物件时会取消选中**（单选情况下）。否则会出现「点过一张卡之后鼠标移开，
它仍是选中状态、描边还亮着，按 F 还会翻它」的怪现象。

两种情况下刻意**不**清，因为清了反而难用：

- **正在拖拽** —— 拖拽途中鼠标必然会「离开」被拖的物件（它被排除在拾取之外），
  一移动就清的话拖到一半就丢选中了。
- **多选**（框选 / `Ctrl`+点选建立的多于一个）—— 那是刻意建立的集合，
  不该被一次鼠标移动冲掉，否则框选完立刻失效。多选要取消用 `Esc` 或点空白。

> 网格吸附用独立开关而不是修饰键，因为它是**持续状态**而非一次性动作。
> `Shift` 因此腾出来做「从堆中抽单张」。

## 怎么验证

不靠肉眼看图，靠**可复现的机械断言**：

```powershell
powershell -File tools/dev/shot.ps1 -Name m2_objects -Frames 50
```

它会拉起游戏、等 N 帧、截图、跑自检、退出（**不需要窗口焦点**，可反复执行）。产出三份东西：

- `.dev/shots/<名字>.png` —— 画面
- `...png.meta.json` —— 分辨率 / 采样颜色数 / 平均亮度
- `...png.report.json` —— 自检报告

报告里的证据分五类：

1. **字体**：用 `Font.HasChar` 逐字检查中文码位是否有字形 → `verdict: CJK_OK`
2. **像素**：分区域统计主色与颜色数 → 桌面主色应精确等于 `BoardTheme.BackgroundColor`
3. **UI**：关键 `Control` 的实际矩形与文本 → 检查有没有跑出屏幕、有没有被压成 0 宽
4. **相机**：缩放锚点不变量 —— 缩放前后该屏幕点下的世界坐标必须不变
5. **物件与输入**：用 `Input.ParseInputEvent` 往真实输入管线塞伪造鼠标/键盘事件，
   验证从「输入路由 → 物件管理器 → 节点状态」整条链路

### 最近一次实测（M2）

| 断言 | 结果 |
|---|---|
| 字体中文覆盖 | `CJK_OK`，30+ 探针字零缺字形 |
| 相机缩放锚点漂移 | `0.0 px` |
| 中键拖拽平移误差 | `0.00008 px` |
| 拖拽物件位移误差 | `0.0 px` |
| 步进旋转 | 恰好 `+15.0°` |
| 翻面 | 状态翻转 ✓ |
| 拖放成堆 | 两张并成堆 #1，pile id 一致 ✓ |
| 框选 | 选中 2 个，且物件位移 `0.0 px`（框选不该动物件） |
| 掷骰 | 点击即掷、动画停稳、结果落在 `[1, Sides]` |
| 桌面区域采样颜色数 | M1 的 7 → **1905**（卡面文字在渲染） |

## 几个关键设计决定

**1. 数据用 POCO + JSON，不用 Godot `Resource`/.tres**
存档要可读、可手改、可 diff —— 对调试工具这比二进制化重要得多。
`Color` / `Vector2` 走自定义 JsonConverter，JSON 里就是 `"#3b4252"` 这种能直接改的写法。

**2. 卡面用 `_Draw()` 合成，不用 `Control` 节点树**
一张卡 = 1 个 `Node2D`。几百张卡时 Control 的 layout 开销会炸，
而 `Node2D` 天然支持自由旋转缩放，和「像素级自由拖拽」的交互模型完全契合。

**3. 卡牌字段是 `List<CardField>` 而非固定属性，且支持实例级覆盖**
玩法验证时字段集合本身就在变（今天 cost/atk/hp，明天加「关键词」），
所以字段必须是数据。而改某一张卡的数值不该污染定义、更不该影响牌库里另外三张同名卡 ——
这是验平衡性时的核心操作。

**4. 相机目标值与当前值分离**
所有数学（尤其是「鼠标下的世界点保持不动」）作用在目标值上，
每帧用指数平滑逼近当前值。这样既平滑，又不会因为 Godot 相机变换晚一帧生效而算错锚点。

**5. 输入只有一处入口**
`ViewportController` 是唯一的输入路由，物件系统通过 `IWorldPicker` /
`IWheelHandler` 接口被"问"而不是自己去抢 `_UnhandledInput`。
否则谁先拿到事件取决于节点顺序 —— 那种 bug 极难查。

**6. 堆是纯逻辑分组，不新增节点**
成员仍是容器节点的直接子节点，只是位置对齐、绘制次序排成连续。
于是「拆堆」「并入」都是纯数据操作，没有节点增删，也就没有生命周期与释放顺序的坑。

**7. HUD 用 VBox + 弹性 Spacer，不用锚点的 `minsize` 模式贴底**
M1 实测踩过：用 `anchor_preset=bottom_wide` 的 `minsize` 模式时，
容器最小尺寸还没算出来，偏移量按 0 计算，提示条被推到 `y=1080`（屏幕外）、
吐司被压成 1px 宽。声明式布局免疫这类时序问题。

**8. .ps1 脚本一律纯 ASCII**
Windows PowerShell 5.1 对无 BOM 的 UTF-8 文件按 ANSI 解码，
中文会变乱码并撑破字符串引号导致解析失败。C#/GDScript/文档里的中文不受影响。

## 自检的两条硬规矩

写自动化断言时踩过的坑，记在这里免得重犯：

1. **不要写死帧数。** 帧率随环境变化（本机实测跑在 ~165 FPS，不是 60）。
   骰子动画最初写死等 110 帧，结果动画根本没跑完就判定失败。
   现在一律**轮询直到条件成立**。
2. **不要写死屏幕坐标。** 桌面内容一变，写死的点就可能正好压在物件上，
   于是「点空白」根本没发生、断言假失败。现在一律**运行时探测**
   （空位、屏幕内目标）。

还有一条更隐蔽的：**聚合判定里的键名必须和子项写入的键名一致**。
曾经写成 `duplicate_ok` 而实际是 `dup_ok`，导致五项子断言全绿却报失败，
差点去改本来正确的产品代码。测试说谎比不测更危险。
